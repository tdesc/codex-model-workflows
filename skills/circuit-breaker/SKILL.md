---

# Circuit Breaker

1. Identify the requested delivery point and the observable that proves it. For a local bug, use its closest normal entry point. For a visual defect, check the relevant geometry or behavior in the browser.
2. Form one concrete source hypothesis and run the smallest check that could overturn it. If the cause is directly visible, use that observation. If several credible causes remain, move to `hypothesis-driven-closed-loop` without expanding the task.
3. Apply the smallest authorized correction and run the focused before/after or regression check. Repeat only if new evidence changes the next action. Keep unrelated changes outside the patch.
4. When the same attempt yields the same blocker, stop that route. Use a cheaper authorized path if it can deliver the outcome. Report the concrete remaining blocker if you cannot continue.

For requested publication, follow the repository's packaging rules. Verify the actual diff, checks, and publication state. Report each stage at the level you observed.
