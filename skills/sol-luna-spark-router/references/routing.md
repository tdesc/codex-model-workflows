# Routing and model availability

## Start with one host

| Work shape | Default route |
| --- | --- |
| Ambiguous diagnosis, coupled implementation, integration, or ordinary serial execution | GPT-6.2 Sol in the active session where supported |
| Independent read-only finding or bounded implementation with complete context and a decisive check | A permitted worker only if the host can do useful parallel work or needs independent evidence |
| A small transformation or patch proposal with compact context and an executable check | A supported Luna or Spark route may be suitable when the requested scope allows it |

A smaller model is an option for a defined contract. Leave final diagnosis and integration with the host. Choose the shortest route to a verified result, including dispatch, validation, and likely repair. Select only reasoning settings supported by the active surface. Give a hard discriminator the effort its uncertainty warrants.

## Verify the active surface

Use `gpt-6.2-sol` for the GPT-6.2 Sol route. The standalone CLI can select it with `codex -m gpt-6.2-sol` when available. In an existing session, inspect the model setting where exposed. A prompt or skill can express a preference but cannot change or attest to the host model.

For any additional worker, resolve the exact supported model ID and settings from the actual dispatch surface and project rules. A model available in one UI or an API catalog may be unavailable in the current subagent tool. Family names such as Luna and Spark do not pin a release or grant access. Record requested model, configured model when observed, reported execution model when available, and actual transport as separate fields. See [Codex model guidance](https://developers.openai.com/codex/models/).

- **Native subagents:** use an admitted route with its actual model, context inheritance, ownership, and lifecycle constraints. Send a complete bounded work packet.
- **Existing tasks:** continue only tasks in scope. Treat a message that starts a turn as an execution action. Preserve existing model settings unless an authorized change is intended.
- **New tasks and runners:** use only when the task authorizes that surface and current policy supports it. Check cwd, source, permissions, output path, model, and process identity. Do not change auth, global model configuration, or provider to get around a denied route.

## Adapt from evidence

Record whether a blocked route lacks a model, transport, quota, capability, or policy admission. Use an authorized fallback only when it meets the task's model requirement. Find the existing run before retrying an unresolved dispatch. A semantic failure warrants a new discriminator, corrected input, or capable authorized route. A timeout only establishes that the wait ended.

For a model comparison, use the same source, task inputs, acceptance criteria, and resource envelope. Record time to an accepted result including retries, verification, and integration. Preserve initial and repaired results separately. Report usage or savings only from measurements.
